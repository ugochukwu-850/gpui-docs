<TabItem label="src/main.rs">

```rust
use gpui::{
    div, prelude::*, px, rgb, size, App, Bounds, Context, SharedString,
    Window, WindowBounds, WindowOptions,
};
use gpui_platform::application;

struct HelloWorld {
    text: SharedString,
}

impl Render for HelloWorld {
    fn render(&mut self, _window: &mut Window, _cx: &mut Context<Self>) -> impl IntoElement {
        div()
            .flex()
            .flex_col()
            .gap_3()
            .bg(rgb(0x505050))
            .size(px(500.0))
            .justify_center()
            .items_center()
            .text_xl()
            .text_color(rgb(0xffffff))
            .child(format!("Hello, {}!", self.text))
    }
}

fn main() {
    application().run(|cx: &mut App| {
        let bounds = Bounds::centered(None, size(px(500.), px(500.)), cx);
        cx.open_window(
            WindowOptions {
                window_bounds: Some(WindowBounds::Windowed(bounds)),
                ..Default::default()
            },
            |_, cx| cx.new(|_| HelloWorld { text: "World".into() }),
        )
        .unwrap();
        cx.activate(true);
    });
}
```

<h2 class="section-title">Why GPUI?</h2>
<p class="section-sub">Most desktop UI toolkits make you choose between speed and a pleasant way to write code. GPUI aims for both.</p>

<div class="feature-grid">
  <div class="feature"><div class="ico">⚡</div><h3>Drawn on the GPU</h3><p>There is no browser or web view inside. GPUI draws every frame itself on your graphics card, which is how Zed stays smooth with huge files.</p></div>
  <div class="feature"><div class="ico">🦀</div><h3>Just Rust</h3><p>Your state, your layout and your event handlers live in one language. No HTML, no JavaScript, no bridge between them.</p></div>
  <div class="feature"><div class="ico">🎨</div><h3>Styling you already know</h3><p>Style with chained methods like <code>.flex()</code>, <code>.gap_3()</code> and <code>.bg(...)</code>. If you have used Tailwind, it will feel familiar.</p></div>
  <div class="feature"><div class="ico">🧩</div><h3>Three levels of control</h3><p>Use simple views for most screens, and drop down to low-level elements when you need a custom editor or a huge list.</p></div>
  <div class="feature"><div class="ico">⌨️</div><h3>Keyboard first</h3><p>Actions and key bindings are built in, so shortcuts, focus and command palettes are natural to build.</p></div>
  <div class="feature"><div class="ico">🖥️</div><h3>macOS, Windows, Linux</h3><p>One codebase. Each platform has its own native window backend underneath.</p></div>
</div>

<h2 class="section-title">Coming from React?</h2>
<p class="section-sub">You already know most of the ideas. Here is how they map across.</p>
